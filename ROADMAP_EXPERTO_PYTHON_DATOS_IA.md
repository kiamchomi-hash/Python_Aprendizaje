# Hoja de Ruta Experto Python, Datos e IA

## Objetivo

Adquirir dominio profesional y demostrable en Python, backend, bases de datos, datos, automatizacion, IA introductoria, calidad, despliegue, observabilidad y herramientas de trabajo moderno.

El objetivo principal es empleabilidad. El criterio de avance no es solo completar cursos o leer documentacion, sino construir proyectos, documentarlos, probarlos y poder explicarlos en una entrevista tecnica.

Ritmo elegido: 40 horas por semana.

Duracion estimada: 9 a 12 meses.

## Vista General

| Fase | Prioridad | Duracion estimada | Resultado esperado |
|---|---:|---:|---|
| Fase 1: Cimientos | Maxima | 6 a 8 semanas | Base solida en Python, SQL, terminal, Git, seguridad y gestion de conocimiento |
| Fase 2: Desarrollo, Datos e IA Introductoria | Alta | 8 a 10 semanas | APIs, autenticacion, datos, notebooks, automatizacion e IA conceptual |
| Fase 3: Especializacion, Calidad y Orquestacion | Media | 14 a 18 semanas | Testing, Docker, pipelines, scraping, CI/CD, observabilidad, datos avanzados e IA aplicada |
| Fase 4: Entorno Profesional y Visibilidad | Cierre | 6 a 8 semanas | Portfolio, demos, comunicacion profesional, productividad y herramientas colaborativas |

## Rutina Semanal

Distribucion para 40 horas por semana:

| Bloque | Horas | Objetivo |
|---|---:|---|
| Estudio guiado y documentacion oficial | 20 h | Leer, ver cursos, tomar apuntes y entender conceptos |
| Ejercicios practicos | 10 h | Resolver problemas, practicar sintaxis, consultas y herramientas |
| Proyecto aplicado | 6 h | Construir entregables reales y subirlos a GitHub |
| Documentacion | 2 h | README, notas en Obsidian, diagramas y bitacora tecnica |
| Repaso y evaluacion | 2 h | Refactor, pruebas, revision de errores y plan de la semana siguiente |

Rutina diaria sugerida:

- 4 h de aprendizaje profundo.
- 2 h de practica.
- 1 h de proyecto.
- 1 h de documentacion, Git y revision.

## Fase 1: Cimientos Profesionales

Duracion estimada: 6 a 8 semanas.

### Objetivo

Dominar programacion base, terminal, Git, SQL inicial, gestion de conocimiento y seguridad personal.

### Recursos

- Python Programming MOOC - Universidad de Helsinki
- SQLBolt
- DBeaver
- The Linux Command Line
- Oh My Zsh
- Documentacion Oficial de Git
- Obsidian
- Bitwarden

### Entregables

- Repositorio de ejercicios Python.
- Base de datos local con consultas SQL documentadas.
- Flujo Git basico: commit, branch, merge, remote y pull request.
- Vault de Obsidian para apuntes tecnicos.
- Bitwarden configurado para credenciales, tokens y claves.
- Cheatsheet personal de terminal, Git, Python y SQL.

### Plan Paso a Paso

1. Configurar entorno base: Python, editor, terminal, Git, Obsidian y Bitwarden.
2. Completar ejercicios diarios del MOOC de Helsinki.
3. Crear un repositorio para ejercicios Python con commits frecuentes.
4. Completar SQLBolt y replicar consultas en una base local con DBeaver.
5. Practicar comandos de terminal hasta poder navegar, buscar, crear archivos y ejecutar scripts sin interfaz grafica.
6. Leer y practicar Git con ramas, merges, conflictos simples y remotos.
7. Crear notas atomicas en Obsidian para cada tema importante.
8. Cerrar la fase con un proyecto CLI.

### Proyecto de Cierre

Crear una aplicacion CLI en Python para gestionar tareas o gastos personales.

Requisitos:

- Persistencia en SQLite.
- Operaciones de alta, baja, modificacion y listado.
- Busqueda o filtrado.
- README con instalacion, uso y ejemplos.
- Historial de Git claro.

### Criterio de Avance

- Escribir scripts Python simples sin copiar.
- Usar terminal a diario.
- Consultar SQL basico con filtros, joins, agregaciones y ordenamientos.
- Mantener repositorios limpios, con README y commits descriptivos.
- Explicar el proyecto CLI de punta a punta.

## Criterios Globales de Dominio

Para considerar una herramienta o tema como dominado:

- Podes explicar para que sirve y cuando no usarlo.
- Podes crear un ejemplo funcional desde cero.
- Podes resolver errores comunes sin depender totalmente de tutoriales.
- Podes documentar el uso con tus propias palabras.
- Podes integrarlo en un proyecto real.
- Podes defender decisiones tecnicas en una entrevista.

## Reglas de Ejecucion

- No avanzar de fase sin proyecto de cierre.
- No contar un recurso como completado si no hubo practica.
- No guardar secretos en codigo ni repositorios.
- Usar Git desde el primer dia.
- Documentar errores y soluciones.
- Priorizar documentacion oficial cuando exista.
- Convertir cada aprendizaje importante en una nota de Obsidian.
- Mantener cada proyecto ejecutable desde cero.

## Checkpoint Mensual

Al final de cada mes responder:

- Que puedo construir hoy que no podia construir antes?
- Que herramienta entiendo solo superficialmente?
- Que proyecto demuestra mejor mi progreso?
- Que parte podria explicar en una entrevista?
- Que parte necesita refuerzo?
- Que debo eliminar, simplificar o posponer?
